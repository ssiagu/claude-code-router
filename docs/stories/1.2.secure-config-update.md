## Dev Notes

### 现有系统集成信息

**相关配置管理模块** (`src/utils/index.ts`):
- `readConfigFile()`: 已有的配置读取功能，支持JSON5解析和环境变量插值
- `writeConfigFile()`: 已有的配置写入功能，包含目录创建
- `backupConfigFile()`: 已有的备份功能，保留最近3个备份，自动清理旧备份
- `HOME_DIR`, `CONFIG_FILE`: 已定义的路径常量

**配置文件结构** (基于现有系统):
```json
{
  "PORT": 3456,
  "Providers": [
    {
      "name": "provider_name",
      "api_base_url": "https://api.example.com",
      "api_key": "key",
      "models": ["model1", "model2"]
    }
  ],
  "Router": {
    "default": "provider_name,model1",  // 这是我们唯一修改的字段
    "longContext": "...",
    "background": "...",
    "think": "..."
  }
}
```

**安全性考虑**:
- **输入验证**: 严格验证provider和model格式，防止特殊字符注入
- **文件权限**: 确保配置文件权限正确 (读写仅限当前用户)
- **原子性**: 使用临时文件 + 重命名的方式保证原子性写入
- **并发控制**: 使用文件锁或进程锁防止同时修改

**性能优化**:
- 最小化文件I/O操作
- 仅读取和修改必要的配置部分
- 异步操作避免阻塞

**错误恢复策略**:
- 配置验证失败 → 立即恢复备份
- 文件写入失败 → 保留原配置不变
- JSON解析失败 → 报告具体错误位置

### Testing

**测试标准**:
- **测试文件位置**: `tests/utils/configUpdate.spec.ts`
- **测试框架**: Jest + Mock文件系统
- **测试环境**: 隔离的临时目录
- **覆盖率要求**: > 95% (安全关键功能)

**并发测试场景**:
```typescript
describe('Concurrent Config Updates', () => {
  it('should handle multiple simultaneous updates safely', async () => {
    const promises = Array(10).fill(0).map(() => 
      updateDefaultModel('test', 'model')
    );
    const results = await Promise.all(promises);
    expect(results.every(r => r.success)).toBe(true);
  });
});
```

**故障注入测试**:
- 模拟磁盘空间不足
- 模拟文件权限错误
- 模拟进程中断
- 模拟配置文件损坏

**完整性验证测试**:
- 验证JSON格式保持有效
- 验证所有现有配置项保持不变
- 验证只有Router.default被修改
