## Dev Notes

### 现有系统集成信息

**相关源代码树结构**:
```
src/
├── utils/
│   ├── index.ts          # 配置文件读写管理
│   ├── router.ts         # 模型验证和路由逻辑  
│   └── cache.ts          # 会话缓存管理
├── middleware/
│   └── commandParser.ts  # 现有/model命令解析逻辑
└── cli.ts                # CLI命令路由入口
```

**技术集成要点**:
- **配置管理**: 复用 `utils/index.ts` 中的 `readConfigFile()` 和 `writeConfigFile()` 函数
- **模型验证**: 参考 `utils/router.ts` 中现有的模型验证模式和 `middleware/commandParser.ts` 中的 `validateModelExists()` 函数
- **错误处理**: 遵循现有CLI命令的错误处理模式，返回清晰的错误信息
- **TypeScript规范**: 保持与项目现有代码风格一致

**核心接口设计** (基于架构文档):
```typescript
// 模式命令执行结果
export interface ModeCommandResult {
  success: boolean;
  message: string; 
  previousModel?: string;
  newModel?: string;
  availableModels?: string[];
}

// 解析后的模型信息
export interface ModelParsed {
  provider: string;
  model: string;
  original: string;
}
```

**配置文件结构** (来自现有系统):
- 配置文件位置: `$HOME/.claude-code-router/config.json`
- 默认模型配置路径: `config.Router.default`
- 提供商配置路径: `config.Providers[]`

**性能要求**:
- 命令执行时间 < 500ms
- 文件I/O操作采用异步模式
- 内存使用效率优化

### Testing

**测试标准**:
- **测试文件位置**: `tests/utils/modeCommand.spec.ts`
- **测试框架**: Jest (与项目现有测试保持一致)
- **覆盖率要求**: > 90%
- **测试模式**: 单元测试，使用Mock对象模拟外部依赖

**关键测试场景**:
- parseModelString函数: 有效格式, 无效格式, 空字符串, 特殊字符
- executeModeCommand函数: 无参数显示, 有效模型切换, 无效模型处理
- getCurrentDefaultModel函数: 正常配置, 损坏配置, 缺失配置

**Mock策略**:
- Mock `utils/index.ts` 的文件读写操作
- Mock配置对象结构，包含典型的Providers和Router配置
